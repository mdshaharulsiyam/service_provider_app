SALON APP COMPLETION PLAN
Generated from: salon_app_feature_list.html
Repo context:
- Backend: booking_app_backend, Express + TypeScript + MongoDB/Mongoose.
- Mobile app: service_provider_app, React Native.
- Existing backend modules include auth, verification, business, service, service listing,
  booking, notifications, review, message/conversation, payment, coupon, settings,
  overview, category, banner, and location data.
- Existing app screens still use some TaskAlley/task/provider naming, so salon-specific
  naming and workflows must be cleaned up during implementation.

GOAL
Build a complete salon booking platform with these v1 roles:
- Admin
- Salon owner
- Worker
- Customer

Recommended role mapping from current code:
- ADMIN / SUPER_ADMIN -> Admin
- VENDOR -> Salon owner
- PROFESSIONAL or a new WORKER role -> Worker
- USER -> Customer

V1 FEATURE MODULES
1. Auth and user management
2. Salon and worker management
3. Service management
4. Booking and slot system
5. Notifications and reminders
6. Ratings and reviews
7. Points and loyalty
8. Communication and disputes
9. Admin panel
10. Location backend support

FUTURE SCOPE, NOT V1
- Interactive map view
- Points redemption for discounts/free services
- Separate worker-only app

PRIORITY KEY
- P0: Must finish for usable v1.
- P1: Important polish or business rule.
- P2: Nice-to-have after stable v1.

EDGE CASE CHECKLIST
============================================================

- Phone number is unique across all roles.
- Suspended account cannot login or book.
- Deleted account data is anonymized, not hard deleted.
- Salon global booking cap cannot be exceeded.
- Worker cannot be booked outside working hours.
- Service duration blocks the full time range.
- Slots display in customer local timezone and store in UTC.
- Closed days and worker-off days create no slots.
- Customer has only one active booking per salon.
- Same customer/service/slot duplicate booking is blocked.
- Late cancellation requires admin approval.
- Cancelled slot is released immediately.
- Same-day repeated cancellations are flagged.
- No-show can only be marked after slot end/grace period.
- Last-minute booking reminder sends immediately.
- One review per completed booking.
- Review edit locks after 24 hours.
- Cancelled/no-show bookings earn no points.
- Dispute cannot be opened after 48 hours from booking end.

============================================================
DEFINITION OF DONE FOR V1
============================================================

- Customer can register, find a salon, book a service, receive notification,
  cancel when allowed, chat about the booking, and review after completion.
- Salon owner can register salon, manage salon profile, workers, services,
  schedules, bookings, reviews, and customer communication.
- Worker can login, see assigned bookings, receive reminders, chat, and mark
  work progress/completion/no-show.
- Admin can approve salons, manage users, manage bookings, resolve disputes,
  moderate reviews, and configure core platform settings.
- Booking capacity and time-slot rules are enforced by backend, not only mobile UI.
- Backend builds successfully.
- Mobile app runs successfully.
- Critical flows are tested manually and with focused backend tests.
